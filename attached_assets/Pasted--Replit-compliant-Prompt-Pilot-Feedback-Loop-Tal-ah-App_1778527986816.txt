# Replit -compliant Prompt — Pilot Feedback Loop 
## Tal'ah App | Feature: In-App Rating Prompts, Micro-Surveys & Exit Survey\n\n---\n\n## Context\n\nThis is a pnpm monorepo. Key paths:\n\n- Mobile app (Expo + React Native): `artifacts/talah/`\n- API server (Express 5): `artifacts/api-server/src/`\n- Database schema (Drizzle ORM): `lib/db/src/schema/`\n- Admin dashboard (React + Vite): `artifacts/admin/src/`\n\nThe app already has:\n- A `feedbackTable` in `lib/db/src/schema/feedback.ts` with fields: `id`, `groupId`, `fromUserId`, `rating` (1–5), `comment`, `wouldMeetAgain` ('yes'|'maybe'|'no'), `connections` (jsonb), `createdAt`\n- A working post-event feedback screen at `artifacts/talah/app/feedback/[id].tsx`\n- `POST /api/feedback` and `GET /api/admin/feedback` routes\n- `DataContext` in `artifacts/talah/contexts/DataContext.tsx` that fetches the user's groups and requests on login\n- Account deletion in `artifacts/talah/app/(tabs)/profile.tsx` via `handleDelete()` → `removeUser()` → `DELETE /api/users/me`\n- Design tokens: Sand `#F4EDE4`, Olive `#4A5D4F`, Gold `#C8A96A`, Charcoal `#2B2B2B`\n\n---\n\n## What to Build\n\nBuild three distinct feedback mechanisms. Do not modify the existing `feedbackTable` schema or the existing `/feedback/[id].tsx` screen.\n\n---\n\n### 1. Database — New `surveys` Table\n\nAdd `lib/db/src/schema/surveys.ts`:\n\n```ts\nexport const surveysTable = pgTable("surveys", {\n  id:        uuid("id").primaryKey().defaultRandom(),\n  userId:    uuid("user_id").notNull().references(() => usersTable.id, { onDelete: "cascade" }),\n  type:      text("type").notNull(),       // 'micro' | 'exit'\n  responses: jsonb("responses").notNull(), // free-form key-value answers\n  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),\n});\n```\n\nExport it from `lib/db/src/schema/index.ts`. Run `pnpm --filter @workspace/db run push` to apply.\n\n---\n\n### 2. API Routes\n\n#### 2a. `POST /api/surveys`\nAuth: User token required.\n\nRequest body (validated with Zod):\n```ts\n{ type: 'micro' | 'exit', responses: Record<string, string> }\n```\n\nBehaviour:\n- Insert one row into `surveysTable` with `userId` from the auth token.\n- Return `201 { id }`.\n- A user may submit multiple surveys of the same type (do not deduplicate — pilot data is valuable).\n\n#### 2b. `GET /api/admin/surveys`\nAuth: Admin token required.\n\nReturns all rows from `surveysTable`, ordered by `createdAt` descending.\nJoin `users` to include `nickname` and `city` alongside each response.\n\n#### 2c. `GET /api/groups/:id/feedback-pending`\nAuth: User token required.\n\nReturns `{ pending: boolean }`.\n- `pending: true` if:\n  - The group exists, the requesting user is a member,\n  - `group.meetupAt` is in the past (< `Date.now()`),\n  - No row exists in `feedbackTable` where `groupId = :id` AND `fromUserId = currentUser.id`.\n- `pending: false` otherwise.\n\n---\n\n### 3. Mobile App — Post-Event Rating Prompt\n\n**Where:** `artifacts/talah/app/(tabs)/upcoming.tsx`\n\n**Trigger logic (client-side):**\n\nAfter `DataContext` loads, find any group where:\n- `group.meetupAt` is defined and in the past (unix timestamp < `Date.now()`)\n- `group.status === 'completed'` (or `meetupAt` is within the past 72 hours)\n- The user has not yet submitted feedback (call `GET /api/groups/:id/feedback-pending` on mount; cache result in local state)\n\n**UI — Feedback Prompt Card:**\n\nRender a styled card at the top of the groups list in `upcoming.tsx`, above any pending requests. The card should:\n\n- Have an olive left-border accent\n- Show the Arabic text: **"كيف كانت طلعتك؟"** and English sub-text: *"Rate your experience — it takes 30 seconds."*\n- Show a star row (5 tappable stars, Feather `star` icon, gold when selected)\n- Show a primary Button labelled **"Rate Now"** that navigates to `/feedback/[groupId]`\n- Show a small "Remind me later" text link (dismisses the card for the current session only — do not persist dismissal)\n\nIf multiple groups are pending feedback, show only the most recent one (highest `meetupAt`).\n\nDo not show the prompt if the user already has a pending request waiting for a match — the upcoming screen is already active.\n\n---\n\n### 4. Mobile App — Micro-Survey\n\n**Purpose:** Capture early signal from users who are in onboarding or waiting for their first match.\n\n**Trigger conditions (check in `DataContext` on login):**\n\nShow the micro-survey if ALL of the following are true:\n- User's account `createdAt` is more than 3 days ago\n- User has zero completed groups (no `group.status === 'completed'`)\n- User has not previously submitted a survey of type `'micro'` (check via `GET /api/surveys/submitted?type=micro` — add this lightweight route: returns `{ submitted: boolean }` by checking if a row exists in `surveysTable` for the current user with `type = 'micro'`)\n\n**UI — Micro-Survey Modal:**\n\nA modal (`Modal` from React Native, animated slide-up) with the Tal'ah olive header bar. Questions:\n\n**Q1 — How did you hear about Tal'ah?** (single-select chip row)\nOptions: صديقة / Friend, إنستغرام / Instagram, تيك توك / TikTok, واتساب / WhatsApp, أخرى / Other\n\n**Q2 — What are you most looking forward to?** (single-select chip row)\nOptions: لقاء أشخاص جدد / Meeting new people, تجارب المطاعم / Dining experiences, محادثات ذات معنى / Meaningful conversations, كل شيء / All of it\n\n**Q3 — One word to describe what you hope Tal'ah will be for you:** (free text `Input`, optional, max 40 chars, Arabic placeholder)\n\nSubmit button: **"أرسل" / Submit** — calls `POST /api/surveys` with `{ type: 'micro', responses: { source, expectation, word } }` then closes the modal. Show a brief success toast.\n\nDismiss without submitting: small "X" top-right. If dismissed, do not show again this session. Show again on next login if not yet submitted.\n\n---\n\n### 5. Mobile App — Exit Survey\n\n**Where:** `artifacts/talah/app/(tabs)/profile.tsx`, inside the existing `handleDelete()` function.\n\n**Behaviour:** Before showing the existing `Alert.alert` delete confirmation, first show the exit survey modal. Only after the survey is submitted (or explicitly skipped) proceed to the deletion `Alert.alert`.\n\n**UI — Exit Survey Modal:**\n\nHeader: **"قبل أن تغادري" / "Before you go"**\nSubtext: *"Your feedback helps us improve Tal'ah. It takes 20 seconds and is anonymous."*\n\n**Q1 — Why are you leaving?** (single-select, required)\nOptions (Arabic / English):\n- المناطق المتاحة محدودة / Limited cities available\n- المجموعات لم تناسبني / Groups were not the right fit\n- مخاوف الخصوصية / Privacy concerns  \n- أخذ استراحة / Taking a break\n- أخرى / Other\n\n**Q2 — Any last thoughts?** (optional free text, max 200 chars, Arabic placeholder, `Input` component)\n\nTwo buttons:\n- **"أرسل وتابع" / "Submit & Continue"** — calls `POST /api/surveys` with `{ type: 'exit', responses: { reason, comment } }`, then on success triggers the existing delete `Alert.alert`\n- **"تخطَّ" / "Skip"** (text link, no fill) — skips survey, goes directly to the existing delete `Alert.alert`\n\nBoth paths must eventually reach the existing delete confirmation. Do not modify the deletion logic itself.\n\n---\n\n### 6. Admin Dashboard — Surveys Tab\n\n**Where:** `artifacts/admin/src/components/` — create `SurveysTab.tsx`\n\nAdd "Surveys" as a new tab in `artifacts/admin/src/pages/DashboardPage.tsx` alongside the existing tabs (Users, Requests, Groups, Compatibility, Feedback, Reports).\n\n**SurveysTab layout:**\n\n**Summary row** (3 stat cards, same style as existing dashboard stats):\n- Total micro-surveys submitted\n- Total exit surveys submitted\n- Most common exit reason (modal value of `responses.reason` across all exit surveys)\n\n**Micro-Survey Responses table:**\nColumns: Date | User (nickname, city) | Source | Expectation | Word\nSorted by date descending. Paginate at 20 rows.\n\n**Exit Survey Responses table:**\nColumns: Date | User (nickname, city) | Reason | Comment\nSorted by date descending. Paginate at 20 rows.\n\nUse the existing `lib/api.ts` typed fetch wrapper pattern from `artifacts/admin/src/lib/api.ts` to call `GET /api/admin/surveys`.\n\n---\n\n## Constraints\n\n- All new text must support Arabic (RTL) and English. Follow the existing `useT()` / `i18n` pattern in the mobile app.\n- Use existing components: `AppText`, `Button`, `Card`, `Input`, `Chip`, `ScreenHeader` from `artifacts/talah/components/`.\n- Use `useColors()` hook for all colour values — do not hardcode hex strings.\n- All new API routes must be registered in the existing Express router files under `artifacts/api-server/src/routes/`. Follow the existing auth middleware pattern (`requireUser`, `requireAdmin`).\n- Zod validation on all new request bodies.\n- Run `pnpm run typecheck` after implementation.
